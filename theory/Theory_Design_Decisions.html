Theory — Design Decisions

Locked choices for this v1 engine, with the rejected alternatives. Mirrors the README design table and comments in matching_engine.hpp / order_book.hpp.

Book representation

Choice: std::map<price, Level> + std::deque<Order> per level + unordered_map id index.

Why: Sorted best bid/ask via begin(); FIFO is natural; easy to reason about and test.

Rejected for v1: flat tick array, intrusive linked lists, polymorphic order hierarchy. Those are valid upgrades when latency or cancel-in-middle cost dominates.

Price and quantity

Choice: int64_t ticks and lots. No double on the match path.

Why: Exact equality, stable golden tests, matches real tick grids.

Trade price

Choice: Execute at the maker (resting) price.

Why: Standing quote defines the trade; aggressor receives price improvement when their limit is through the market.

Rejected: mid, microprice, or taker-limit pricing.

Market residual

Choice: Cancel unfilled market qty (CancelReason::Residual). Never rest a market order.

Why: A market order has no price at which to rest. Behaviour matches an IOC-style market. Walking successive ask/bid prices still happens until the book is empty.

Rejected: convert residual to a limit at last trade (would invent a price policy).

Order identity

Choice: Caller / scenario supplies order_id; engine rejects duplicates while the id is live.

Why: Deterministic scripts without capturing auto-assigned ids.

Rejected for v1: engine-only monotonic ids (fine in production gateways; worse for static golden files).

Event order

Choice: On successful NEW: Accepted → zero or more Trade → optional residual Cancelled.

Why: Stable CLI output; Accepted means “validated,” not “rested.”

Amend / TIF / STP

Choice: Out of scope. Amend = cancel + new. Market residual ≈ IOC market. Self-trades allowed.

Why: Keeps one-day correctness focus; further types live under future work in the README.

Concurrency

Choice: Single-threaded book.

Why: Matching rules first. Production pattern later: shard by symbol onto dedicated threads.

Testing approach

Choice: Hand-rolled G1–G9 in C++ plus scenario DSL twins; zero third-party test frameworks.

Why: Clear portfolio signal; no Catch2/GTest dependency noise.

Companion MDS project

A separate TCP market-data simulator covers wire/session/feed. This repo stops at in-memory match state. Future glue (not v1): gateway → matcher → publish trades/book.

Worked behaviours (same facts as the golden tests)

  • Price-time: better price first; FIFO within a price (G4, G5).
  • Cross prevention: marketable limits match before resting; book stays uncrossed (G8).
  • Partial fill: maker qty shrinks; taker may fully fill without resting (G3).
  • Thin market: market buy takes all asks then cancels leftover (G7).
  • Rejects: bad qty / duplicate id leave the book unchanged (G9).
