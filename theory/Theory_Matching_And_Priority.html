Normative rules

04 — Matching Rules & Priority

This note is normative for our engine — implement exactly this, then document in docs/matching_rules.md.

Price-time priority (FIFO)

When allocating a trade against resting liquidity:

  1. Price priority: always consume the best opposite price first
    • Aggressive buy → lowest ask first, then next lowest, …
    • Aggressive sell → highest bid first, then next, …
  2. Time priority: within a price, consume orders in arrival order (FIFO queue).

No pro-rata, no size priority, no broker preferencing in v1.

Contrast: pro-rata (futures intuition)

At the same price, allocate fills proportional to displayed size (with caps/min lots). Different fairness story; different data structures. Say in review: “Equities-style CLOB is price-time; some futures books are pro-rata or hybrid.”

Match loop (aggressive buy vs asks)

Pseudocode:

function match_buy(taker):
  while taker.remaining > 0 and asks not empty:
    best_price, queue = asks.best()
    if taker.is_limit and best_price > taker.limit_price:
      break   # not willing to pay this much
    // market: never break on price
    while taker.remaining > 0 and queue not empty:
      maker = queue.front()
      q = min(taker.remaining, maker.remaining)
      emit Trade(maker.id, taker.id, price=maker.price, qty=q)
      maker.remaining -= q
      taker.remaining -= q
      if maker.remaining == 0:
        queue.pop_front()
        forget(maker.id)
    if queue empty:
      asks.erase(best_price)
  if taker.is_limit and taker.remaining > 0:
    rest(taker)
  else if taker.is_market and taker.remaining > 0:
    emit Cancelled(taker, residual)

Sell vs bids is symmetric (best_price < taker.limit_price breaks for sell limits).

Trade price convention: maker (resting) price

Each fill executes at the resting order’s price, not the aggressor’s limit.

Example:

  • Ask rests 10 @ 101.
  • Buy limit 10 @ 105 arrives.
  • Trade price = 101 (maker), not 105.

Why venues do this: the resting quote was the standing offer; price improvement goes to the taker. Document in README — this is a core rule of the project.

Not used in v1: mid, microprice, taker limit, or discretionary price.

Walk the book

Large aggressor, multiple levels:

Asks: 10@101, 10@102, 10@103
Market buy 25

Trades:
  10 @ 101
  10 @ 102
   5 @ 103
Residual market: 0 (fully filled)

Average fill = (10·101 + 10·102 + 5·103) / 25 — useful demo narrative for “impact.”

Partial fills

Any trade with q < remaining_before on either side is a partial for that side.

Accounting identity after each submit:

incoming qty = sum(trade qtys) + resting residual + cancelled residual

Golden tests should be able to verify this.

Cancel semantics

  • Remove remaining qty of resting order; adjust level aggregate; drop empty levels.
  • Already filled / unknown → reject.
  • Cancel does not trigger matching (except exotic venues) — book may only widen/thin.

Order identity model (locked for this repo)

  • Scenario supplies order_id.
  • Engine rejects duplicates.
  • Cancel and trades refer to those ids.
  • Deterministic tests without capturing auto-ids.

Alternative (engine-assigned ids) is fine in production gateways; worse for scripted golden files unless the DSL supports bind variables.

Sequence / time

FIFO is defined by order of acceptance onto that price level, not wall-clock.

Implementation: std::deque push_back on rest; pop_front on fill. Optional explicit seq monotonic counter for debugging equality.

Wall-clock timestamps on events are cosmetic for logs; matching must not depend on system_clock.

Invariants (assert in debug / tests)

After every successful mutating API call:

  1. If bids and asks both non-empty: best_bid < best_ask.
  2. All remaining qtys > 0 for live orders.
  3. Every live id appears in exactly one queue position + index.
  4. Level aggregate qty equals sum of order remainings at that price.
  5. No market orders rest on the book.

Edge cases checklist

Case Expected
Exact qty match at one level One trade; both gone; level may disappear
Aggressor larger than top level Multiple trades; walk
Limit exactly at best opposite Marketable; trades
Buy limit = best bid (no ask cross) Rests; joins bid queue FIFO
Empty opposite book + market No trades; residual cancelled
Empty opposite + limit Rests
Duplicate new id Reject; no state change
Cancel twice Second reject
